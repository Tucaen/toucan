# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- A git worktree is a first-class workspace entity, not a per-node side effect. It is created explicitly (canvas context menu -> Worktree), persisted in `WorkspaceState.worktrees`, and rendered as its own `worktreeNode`; session nodes *reference* one via `worktreeId`, so several nodes can share a worktree and closing a node never touches it. `TerminalNodeData.workingDirectory` (resolved in `restoreCanvasWorkspace`/`addSessionNode`) is the only value that may be sent as a `cwd` - `projectPath` is display-only now. A node whose worktree record vanished restores `detachedFromWorktree` and dormant rather than silently falling back to the project checkout. Teardown lives in `src/main/git-worktree.ts` and is evidence-gated: it proves shared git-common-dir and non-primary identity, then reports `WorktreeRemovalBlocker`s for dirty/untracked/stashed/unpublished work; missing evidence produces a blocker, never permission. `isForcibleBlocker` decides what a confirmation may override, and removal never deletes the branch, so forcing can only cost uncommitted and untracked files. `planWorktreeRemoval` in `src/renderer/src/worktree-removal.ts` folds attached-node count into that verdict. See `tests/git-worktree.test.ts` and `tests/worktree-rules.test.ts`.
- Terminal identity has two layers: the workspace persists a durable `sessionId`, while `src/main/terminal-manager.ts` exclusively creates and owns the process `incarnationId` and liveness verdict. Every terminal IPC command and event carries both identities; never route by canvas node ID alone or infer exit from renderer/transport loss. Persisted live terminals hydrate as `unverifiable`; only the process owner's exit callback establishes `exited`.
- `.terminal-node` (canvas chat nodes) is `overflow: hidden`, so any dropdown/menu anchored inside with CSS `position: absolute` clips at that ancestor's edge. `SelectorPicker` in `src/renderer/src/ChatNode.tsx` (the Provider/Model/Effort/Permissions pickers) instead portals its menu to `document.body` and positions it in JS against the trigger button's viewport rect via `computeNodePickerMenuPosition` in `src/renderer/src/node-picker-menu-position.ts`, clamped to stay fully on-screen. Follow the same portal pattern for any new floating menu inside these containers rather than CSS anchoring.
- `promptWhenIdle` in `src/main/acp-session-manager.ts` uses the adapters' advertised `_session/steering` extension while a turn is working, so accepted follow-ups are injected exactly once and the adapter observes them at its next safe boundary without replaying or cancelling the turn; a single non-yielding tool can delay that boundary. Adapters without steering fall back to the non-expiring FIFO `PromptWakeGate` in `src/main/prompt-wake-gate.ts`, drained after turn completion/Stop.
- `withStallGuard`/`StallTimeoutError` (`src/shared/stall-guard.ts`) is the shared "bound a promise that might never settle" primitive — used by `runPrompt`'s ACP turn (main) and `VoiceInputPrototype`'s model load/start (renderer). Reach for it whenever a dependency (subprocess call, worker, external service) could stall without ever resolving or rejecting; it leaves the original promise to settle on its own and only bounds the wrapper's own outcome, so it's safe even when the underlying call can't actually be cancelled.
- `createWorkspaceStore` in `src/main/workspace-store.ts` owns all workspace-canvas persistence. `save()` serializes concurrent calls through an internal promise queue, validates the incoming state, writes it to a temp file via the shared `writeFileDurably` helper (fsynced, and unlinked again on any write failure), promotes the current (still-valid) primary snapshot to a single bounded `<path>.backup` recovery copy, then atomically renames the temp file onto the primary (also unlinking the temp file if that rename choreography fails) — so a crash or a failed save at any point leaves either the untouched old primary+backup or a fully-written new primary, never a torn file or a leaked temp file. `load()` returns a `WorkspaceLoadResult` (`state`, `recovered`, `unrecoverable`): it falls back to the backup and self-heals the primary when the primary is missing/corrupt (`recovered: true`, surfaced by `App.tsx`'s "Recovered from backup" indicator), and when neither primary nor backup validates but at least one of those files exists on disk, it reports `unrecoverable: true` with `state: null` instead of the fresh-install case (`unrecoverable: false`) — callers must never silently seed and autosave a fresh default over `unrecoverable: true`, since that would permanently destroy the last damaged-but-potentially-recoverable copy. `App.tsx` enforces this: on `unrecoverable`, it shows a non-dismissable warning dialog and only seeds a fresh workspace after the user explicitly acknowledges it. Both primary and backup reads go through `parseWorkspaceState`, so schema migrations apply uniformly to either. See `tests/workspace-store.test.ts` for the interruption/corruption/concurrency/unrecoverable scenarios this guarantees.
- Both ACP adapters replay a resumed session as `session/update` notifications during `session/load`. `src/main/acp-session-manager.ts` buffers that finite load-time stream into `AgentCreateResult.replay`, and `useAgentConversation` folds it through the same event handler as live updates; do not send load replay over the separate `agent:event` IPC channel, where renderer startup can lose it. `isInternalNotificationText` filters Claude's synthetic supervision injections at the single point ADE consumes `session/update`. See `tests/restored-chat-transcript.dom.test.tsx` and `tests/acp-session-manager-replay-filter.test.ts`.
- ACP auth-required detection has one home, `isAuthRequired` in `src/main/acp-session-manager.ts`, feeding both `promptFailure` (mid-conversation) and `openSession`'s catch (session creation/resume) so every auth failure reaches the same `{ type: 'auth', methods }` sign-in UI.
- There are two test runners: `tests/**/*.test.ts` (compiled by `tsc -p tsconfig.test.json`, run with `node --test`) covers non-UI logic and has no DOM; `tests/**/*.dom.test.tsx` (Vitest + jsdom + `@testing-library/react`, config in `vitest.config.ts`, setup in `tests/dom/setup.ts`) actually renders renderer components/hooks.
- Transcript markdown lives in `src/renderer/src/MarkdownMessage.tsx` (GFM via `remark-gfm`), and it re-renders on every streaming chunk. Syntax highlighting therefore must not be a rehype plugin — that would re-tokenize every code block in the message per chunk. `pre` is replaced by a `React.memo`'d `CodeBlock` keyed on its own text, so only the block still streaming is re-highlighted; keep that shape for any future per-block work. Markdown links (including GFM autolinks) go through `terminalApi.openExternal` → the `shell:open-external` handler in `src/main/index.ts`, which forwards http/https only; a plain `<a>` would navigate the app window away. See `tests/chat-markdown.dom.test.tsx`.
- Past conversations are browsable and resumable independently of any node: `src/main/conversation-history.ts` enumerates both providers' transcripts for a set of working directories (a project checkout plus its worktrees) and `ConversationHistoryDialog.tsx` (canvas context menu -> History) opens the picked one as a node with `launchMode: 'resume'`. Enumeration is deliberately two-phase - candidates cost a directory entry plus, for Codex, one head read cached by path (a `session_meta` line never changes), and only the requested page's transcripts are read in full - so a project with hundreds of transcripts stays responsive. Claude project folders are matched case-insensitively against `encodeClaudeProjectDirectory` because the same checkout reaches the CLI under either drive-letter case; Codex subagent rollouts (`thread_source: 'subagent'`) are excluded because they are not resumable conversations. A row whose transcript has since been deleted is reported in place via `conversationApi.exists` rather than opening a resume that cannot find its conversation. Codex ACP is deliberately pinned to `1.1.10`/Codex `0.146.1`: Codex `0.147.0` rejects history opened while another client owns the thread as `already has an active writer`; do not lift the pin until the live active-transcript replay case passes. See `tests/conversation-history.test.ts`, `tests/conversation-history-dialog.dom.test.tsx` and `tests/codex-acp-compatibility.test.ts`.
- The composer is a prompt editor, and its decisions live in small pure modules the rendered `Composer` in `src/renderer/src/ChatNode.tsx` only wires together: `composer-keys.ts` (one function decides send vs newline vs history-walk from the workspace-wide `ComposerSendKey`), `prompt-history.ts` (session prompt ring, walked with the arrows from an empty composer), `composer-autosize.ts` (growth bounds), `slash-command-completion.ts` (when a `/` token is a command, how the list narrows, what accepting inserts and where the caret lands), and `prompt-outbox.ts`. The slash list is never hardcoded: it is whatever the session advertised through ACP's `available_commands_update`, normalized by `simplifyAvailableCommands` in `src/main/acp-session-manager.ts` and cached there so reopening an agent isn't left blank. The outbox is the load-bearing one: a follow-up submitted while a turn is working is held *in the renderer*, never handed to `promptWhenIdle`, because a prompt that has crossed into the adapter (steered into the running turn, or parked in the main-process `PromptWakeGate`) can no longer be taken back — that hold is what makes Edit/Withdraw mean anything, and "Send now" is the explicit opt-in back into steering. Decision answers and `sendMessage` deliberately bypass the outbox and still steer immediately, since the agent is actively waiting on them. The outbox drains one prompt per idle turn. Drafts belong to the node (`WorkspaceTerminalNode.draft`), not the ACP session, so they outlive resize, collapse and reload; the Composer debounces them upward through `onDraftChange`. See `tests/composer-prompt-editor.dom.test.tsx` and `tests/composer-queue-while-busy.dom.test.tsx`.
- Tool activity has one home: the transcript. `useAgentConversation` records first-seen message/activity order in `transcript`; `ChatView` interleaves `ActivityCard`s and reasoning cards with dialogue, while per-node `focusMode` hides activity, reasoning, plans, and transient detail without discarding them. `WorkspaceTerminalNode.focusMode` persists the choice and loading migrates legacy `worklogCollapsed`; the right-side rail no longer exists. Every tool call uses the shared `ActivityCard` shell in `ChatNode.tsx`; add families only through `toolCardFamilies` in `tool-card-families.tsx`. `mergeActivity` supplies client-side timing, bodies are line-clamped before the DOM, and a collapsed card reopens if it later fails. Purpose-built cards depend on `activityFromUpdate` preserving tool name, `rawInput`, `rawOutput`, and diffs; claude-agent-acp reports its name through `_meta.claudeCode.toolName`, and a `Write` is `kind: 'edit'` with `oldText: null`, so payload outranks diff shape when identifying it. Paths shorten through `WorkspaceRootsContext`. See `tests/chat-focus-view.dom.test.tsx`, `tests/tool-card-shell.dom.test.tsx`, and `tests/file-operation-cards.dom.test.tsx`.
- Tool calls arrive in one flat feed even when they were not one agent's work, and the two adapters report delegation in two different shapes. claude-agent-acp *nests*: a subagent's own tool calls arrive as ordinary top-level `tool_call` notifications stamped with `_meta.claudeCode.parentToolUseId` (from the SDK's `parent_tool_use_id`), and the spawning `Task`/`Agent` call is stamped `claudeCode.subagent`. codex-acp *never* nests and forwards none of a subagent's tool calls: it reports each interaction with one (`started`/`interacted`/`interrupted`) as its own top-level call under `_meta.codex.subagent`, sharing one `rawInput.agentThreadId` - so that thread id is the only link there is, and those interactions *are* the only progress Codex reports. `delegationOf` in `src/shared/agent-activity.ts` is the only reader of the `_meta`, surfacing `parentToolCallId`/`subagent` on `AgentActivity`; `indexSubagentActivities` owns both links, and `worklog-activities.ts` decides whether a call renders inside its delegation rather than as a separate transcript card. Without all of that, a delegated Read reads as the main agent's and the `Task` card sits at "running" for minutes. Only subagent text/thinking is gated behind the adapter's `subagent-transcript` client capability, which ADE deliberately does not claim - it would route a subagent's prose into the top-level message feed. Todo/task writes are the mirror case: both adapters translate `TodoWrite`/`TaskCreate`/`TaskUpdate` into ACP `plan` notifications and *suppress* the tool call, so the current plan's inline card is normally the only place a plan appears; the exception is a plan write that needed approval, which is surfaced as a real tool call, and `isPlanUpdateFoldedIntoRail` prevents that from becoming a second top-level card. See `tests/task-plan-skill-mcp-cards.test.ts` and `tests/task-plan-skill-mcp-cards.dom.test.tsx`. One ordering constraint the registry depends on: every family's recognizer flattens a tool name to its bare identity (`normalizeToolName` in `tool-input.ts`), so `mcp__tracker__task` and `mcp__docs__grep` collide with built-ins - the MCP family is registered first for exactly that reason, and the delegation/plan/skill recognizers each re-check it.
- What a conversation has consumed is shown per node in the chat's status-bar row, and every decision behind it - the 75%/90% bands, token and cost formatting, clamping, which account window is the one about to bite - is a pure function in `src/renderer/src/session-usage.ts`; `SessionUsageBar.tsx` is markup and does no display maths of its own (a readout hands it a `displayPercent`, already clamped and rounded), and it takes the finished readout rather than raw usage so `ChatNode` knows whether to reserve the grid row at all. Context and cost come from ACP's `usage_update`, forwarded structured, never pre-formatted, as the `usage` `AgentEvent`. The adapters report those fields independently - Claude sends `cost` (USD) only once a turn has produced tokens, Codex sends none at all, and either may report tokens before it knows the window - so an update is folded in by `mergeSessionUsage` as a *patch*: overwriting wholesale would blank a cost or gauge the reader was already shown. For the same reason a token count with no window still renders, just not as a fraction. Account rate limits are per provider, not per session: `App` polls `usageApi.rateLimits()` once and publishes it through `ProviderRateLimitsContext` (`provider-rate-limits.ts`), because each node polling would multiply a read that boots a CLI process. Codex usage comes from app-server's live `account/rateLimits/read` snapshot, bounded by `withStallGuard`, with the newest rollout transcript only as a compatibility fallback; Windows npm `.cmd` shims must resolve to Codex's JS entry point so timeout cleanup cannot strand a child app-server. Both the header's account chips and the node's gauges render `.usage-window` with a `data-level`, so the bands are one CSS rule set (`--usage-warning`/`--usage-critical`) and one window never reads as two different states. See `tests/codex-rate-limits.test.ts`, `tests/session-usage.test.ts` and `tests/session-usage-bar.dom.test.tsx`.
- Assistant decision messages (labeled multiple-choice questions) are recognized by `src/renderer/src/decision-message.ts` from plain text. `src/renderer/src/pending-decisions.ts` owns stable task/key identity, replay/open-wake dedupe, deterministic multi-decision ordering, and resolution folding.
- Recently closed session nodes are a bounded, persisted LIFO stack (`WorkspaceState.recentlyClosedNodes`), populated only through `App.tsx`'s React Flow removal wrapper. `Ctrl+Shift+T` is consumed only when `closedSessionKeyAction` can reopen an entry; `reopenClosedSession` in `canvas-workspace.ts` rebuilds runtime callbacks, resumes the saved conversation/session at its original position, and preserves the detached/dormant safety rule when a referenced worktree has vanished. Keep future session-node close paths routed through that wrapper. See `tests/canvas-workspace.test.ts` and `tests/workspace-store.test.ts`.
