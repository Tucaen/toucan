# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- ADE hosts FirstMate only through Windows' WSL host; `createUnsupportedFirstMateRuntime` in `src/main/firstmate-runtime.ts` refuses every other platform, so there is no second host implementation to extend. ADE hosts the FirstMate captain as an ACP conversation, not a tmux pane. `src/renderer/src/firstmate-project-catalog.ts` gives it the machine-readable ADE project catalog and a hint-only active project; FirstMate resolves each task and pins the selected project/provider carrier from `src/shared/firstmate-task-context.ts` at dispatch. Before calling `fm-spawn.sh`, the dispatch contract requires the captain to validate the pinned context through the managed ADE spawn gate (`$FM_HOME/bin/ade-spawn-gate`); `src/main/firstmate-spawn-gate.ts` owns the pure validation function that checks the context against ADE's authoritative project record and current validator, and the WSL gate script in `src/main/firstmate-runtime.ts` mirrors that logic for the captain to call. The existing lifecycle validation in `taskContextProblem` remains as a corruption/backstop check. Lifecycle, app-native wake, concurrent task-scoped validation, and provider/model wrappers are owned by `src/main/firstmate-lifecycle.ts`, `src/main/firstmate-lifecycle-coordinator.ts`, and `src/main/firstmate-runtime.ts`. Each validation dispatch gets its own no-mistakes home under `state/validators/{scope-hash}/no-mistakes/` so differently-pinned tasks validate concurrently without clobbering each other's pipeline configuration. Before supervising a reported crew worktree, ADE proves read-only that it belongs to the pinned checkout and is not the primary tree: the runtime gathers `git rev-parse` common/dir facts in WSL and `src/main/firstmate-worktree-provenance.ts` owns the verdict; ADE never allocates a worktree of its own. The integration contracts have one home each: `src/shared/firstmate-runtime-record.ts` owns the `ade-runtime.json` record (type, serializer, parser); `src/main/firstmate-environment.ts` owns the ADE/FirstMate variable names and process/tmux env construction; `src/main/firstmate-paths.ts` owns canonical Windows paths and Windows-to-WSL conversion (the renderer consumes registered paths, never deriving them); `errorMessage` in `src/shared/text.ts` owns unknown-error-to-message conversion. Inline WSL programs receive a serialized record or generic key/value args and never restate the schema.
- Sidebar projects are durable external FirstMate projects, never clones under FirstMate's managed `projects` directory. `src/main/firstmate-external-projects.ts` owns identity, canonical paths, posture defaults, collisions, and migration, and `src/main/firstmate-project-origin.ts` owns which origins are accepted. Registration writes only ADE's own file in the private home: `data/projects.md` is firstmate-private and rebuilt from the clones under `projects/`, so ADE reads it and lets an entry recorded there for a checkout outrank ADE's own record. Its format and posture vocabulary belong to the managed distro's `bin/fm-project-mode.sh`. Registration only reads a checkout; anything that would write inside one needs a separate explicit authorization.
- `.firstmate-panel` and `.terminal-node` (canvas chat nodes) are both `overflow: hidden`, so any dropdown/menu anchored inside them with CSS `position: absolute` clips at that ancestor's edge. `SelectorPicker` in `src/renderer/src/ChatNode.tsx` (the Provider/Model/Permissions pickers) instead portals its menu to `document.body` and positions it in JS against the trigger button's viewport rect via `computeNodePickerMenuPosition` in `src/renderer/src/node-picker-menu-position.ts`, clamped to stay fully on-screen. Follow the same portal pattern for any new floating menu inside these containers rather than CSS anchoring.
- The WSL shell scripts in `src/main/firstmate-runtime.ts` are JS template literals that get written through nested *unquoted* heredocs (`<<EOF`, needed so the outer script's variables like `$base`/`$HOME` expand into the generated file). A single backslash before `$` (e.g. `"\$@"`) is not a recognized JS escape, so the JS parser silently drops it before the string ever reaches the shell — the heredoc then sees a bare `$@`/`$name` and expands it immediately against the *outer* script's own (usually empty) context instead of deferring it into the written file. To defer a variable through such a heredoc, write a double backslash in the JS source (`"\\$@"`) so exactly one literal backslash survives into the shell text. `home/bin/claude`/`home/bin/codex` health is verified by content (`WSL_INSPECT_SCRIPT` greps for the literal forwarded-argument invocation, not just `-x`), because a wrapper can be present and executable yet still broken this way.
- Every ACP agent session (not just FirstMate's) gets a `CaptainWakeGate` (`src/main/firstmate-captain-wake.ts`, created in `src/main/acp-session-manager.ts`'s `create()`), so `promptWhenIdle(id, text)` queues-and-delivers-on-idle for any session id. The composer (`Composer` in `src/renderer/src/ChatNode.tsx`, hook logic in `src/renderer/src/use-agent-conversation.ts`) submits through it — `window.agentApi.promptWhenIdle` (IPC `agent:prompt-when-idle`) — whenever `status === 'working'`, so typing while the agent is busy queues rather than blocking; the gate is a real FIFO, so every enqueued message is eventually delivered in submission order, none superseded or dropped (see `firstmate-captain-wake.test.ts`).
